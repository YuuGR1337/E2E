# v0.6.1 — clearer browser failures, iframes, per-step timeouts

An audit drove the page tools the way a planner model does: a login flow, late
elements, animations, overlays, iframes, redirects and network failures, over
raw JSON-RPC. The server never crashed. This release fixes the 11 places where a
failure was labelled wrongly or lost the detail an agent needs to recover.

## Fixed

- **Per-step timeouts.** `actionTimeoutMs` (every page tool) sets how long each
  action waits for its element; it was fixed at 10 seconds, and the timeout
  hint told agents to raise `timeoutMs`, which did not help.
- **Timeouts are no longer called crashes.** A call that runs past `timeoutMs`
  is reported as `TIMEOUT`, not `BROWSER_CRASH` with a reinstall hint.
- **Failed actions say why.** They keep the last lines of Playwright's call
  log and the page URL at that moment, so an element covered by an overlay, or
  a page that redirected to the login screen, is named outright.
- **Iframes.** `frameLocator('#frame')` and `locator('#frame').contentFrame()`
  work in `actions` and in `validate-selector`, and suggested locators keep the
  frame step.
- **Error kinds.** `NAVIGATION_FAILED` covers redirect loops, ports browsers
  refuse and rejected certificates; these were reported as
  `SERVER_NOT_RUNNING`. `INVALID_INPUT` covers bad arguments that are not paths.
- **HTTP status.** An error page (4xx or 5xx) is flagged, and the status is in
  the structured result.
- **validate-selector** takes `waitFor` for elements that render late, and
  returns `valid`, `matches`, `locator` and `httpStatus` as structured fields
  with an output schema.
- **Unknown arguments** are named at the top of the result, with the closest
  real name (`waitfor`, did you mean `waitFor`?), instead of being dropped.
- Tool descriptions say each call starts a fresh browser, so a login belongs in
  the same `actions` list.

No new dependencies. Node 22 or newer, as in 0.6.0.
