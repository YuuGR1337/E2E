# v0.7.0 — saved logins, a heal guard and flaky-test quarantine

Three new tools for the problems teams hit most once an AI agent is fixing their
Playwright suite: signing in (2FA included) without pasting passwords into chat,
"fixes" that make a test green by checking less, and flaky tests that block every
build while someone works on them. All three are free and part of the MIT package,
like every other tool.

## New

- **`save-login`.** Logs in once in a real browser and saves the session as a
  Playwright `storageState` file (default `playwright/.auth/<name>.json`) for
  tests and the page tools. Fill values use `{{env:E2E_PASSWORD}}` and `{{totp}}`:
  the password is read from the server's environment and the authenticator code
  is generated from a TOTP secret (RFC 6238), so neither passes through the
  chat. Only test-looking variables can be read (`E2E_*`, `TEST_*`, `PW_*`,
  `PLAYWRIGHT_*`, `LOGIN_*`, plus names in the new `PW_MCP_LOGIN_ENV`). A
  `verify` check (a page, a locator only a signed-in user sees, a URL the
  session must not land on) decides whether the login worked, and on the next
  call whether the saved session is still good: **SAVED**, **STILL VALID** or
  **LOGIN FAILED**.
- **`check-test-change` (heal guard).** Compares changed spec files with a git
  ref, or a proposed fix with the file on disk, test by test. It blocks a change
  that deletes assertions, removes or skips a test, or adds `.only`, and warns on
  `expect.soft`, weaker matchers (`toHaveText` → `toBeVisible`), new hard waits,
  `force: true`, swallowed errors and raised timeouts, retries or screenshot
  tolerance. The skill now runs it after every test fix.
- **`playwright-e2e-mcp guard`** runs the same check in CI (`--base origin/main`,
  exit 1 on BLOCK, `--strict` to fail on warnings, `--json`), and the GitHub
  Action has a `guard: true` input that runs it on pull requests.
- **`quarantine`.** Quarantines a flaky test with an owner, a reason and an
  expiry (default 14 days, at most 90) in `playwright-quarantine.json`. The test
  keeps running and being reported, but its failure no longer fails `run-test`,
  `get-run-status` or the `ci` command; once the entry expires it blocks again.
  `run.quarantined` in the structured result counts them.
- **Optional Pro CI history client.** With `PW_MCP_PRO_KEY` and `PW_MCP_PRO_URL`
  set, `playwright-e2e-mcp upload` (or the Action's `pro-key` / `pro-url` inputs)
  sends recorded runs to Pro Cloud, and `analyze-history` merges them with local
  runs (`source: local | cloud | both`). Without a key nothing changes and no
  request is made.

## Changed

- Tool profiles: `core` and `triage` include `check-test-change`; `triage` also
  has `quarantine`; `inspect` and `author` include `save-login`.
- All nineteen tool definitions cost about 14k tokens of context (about 4k for
  `core`).

No new dependencies. Node 22 or newer, as in 0.6.0.
