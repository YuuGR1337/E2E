# v0.5.0 — CI reports, breaking commits, flow walking, performance audits

This release closes the gaps left by an October 2026 comparison with other E2E
testing MCP servers: diagnosing CI failures, history that points at the commit
that broke a test, test writing grounded in the live page, and performance.
Everything still runs locally, free and MIT licensed.

## New

- **`load-report`** (tool 14). Loads a CI job's Playwright JSON report, or
  merges a folder of sharded blob reports with the project's
  `playwright merge-reports`. CI paths are mapped onto the local checkout and
  traces are found in the unpacked `test-results` artifact, so `get-failure`,
  `suggest-fix` and `diagnose-flaky` work on CI failures. The run is recorded in
  the history with its commit, branch and build link.
- **`audit-performance`** (tool 13). Lab Web Vitals (LCP, CLS, TBT, FCP, TTFB,
  and INP for clicks and key presses in `actions`) in headless Chromium, with a
  phone preset (4x CPU, slow 4G), the median of up to five runs and optional
  budgets. Names the LCP element and shifting elements as verified locators,
  lists heavy and render-blocking requests, and returns a budget test.
- **History views in `analyze-history`:** `commits` (the first bad commit of
  each failing or flaky test after its last passing streak, with the last good
  one), `slow` (median duration, flagging tests that got slower) and `trend`
  (failed and flaky executions per day). Every run now records its commit.
- **`generate-e2e-test` `steps`: walk the flow.** Runs the steps on the live
  page first and stops at a step that does not work, then writes a spec that
  replays them, asserts the URL and accessibility snapshot where the flow
  landed, and runs it once to prove it passes.
- **`inspect-page` `view: "aria"`.** The accessibility snapshot of the page or a
  selector, with a ready `toMatchAriaSnapshot` assertion.
- **Page state for every page tool:** `routes` (up to 20 network mocks: fulfil,
  abort or delay), `har` (record traffic to a HAR file inside the project, or
  replay it) and `browser` (`chromium`, `firefox` or `webkit`; performance
  audits stay Chromium-only, and WebKit is refused while private addresses are
  blocked).
- **`suggest-fix` handles strict mode violations.** It uses the unique locator
  Playwright prints for the intended match, picking the exact-name match itself
  or the `candidate` you pass.

## Fixed

- With configs that have no named projects, the `suggest-fix` verification
  re-run failed with "Invalid project name" and left the unverified edit in the
  spec. Empty project names are now treated as none, and the edit is reverted
  if the re-run cannot start.

## Changed

- Fourteen tools; all definitions cost about 9k tokens of context, the `core`
  profile about 2.3k (unchanged). The `triage` profile includes `load-report`.
- No new dependencies.
